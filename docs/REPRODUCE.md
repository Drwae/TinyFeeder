# Reproducing the article's experiments on AV-FFIA

All numbers in the article are produced by the steps below, on the public
AV-FFIA dataset, from one run folder (`runs/avffia/`). Every table is
generated by `scripts/paper_tables.py` from the saved test predictions, so
no number is copied by hand.

Expected compute: one NVIDIA GPU with ≥16 GB (24 GB recommended), ≥32 GB RAM,
~200 GB free disk; about 1–2 days of GPU time in total. An NVIDIA Jetson Nano
(JetPack 4.6+, TensorRT) is needed for the on-device latency and power numbers.

## 0. Environment (GPU server)

```bash
conda create -n tinyfeeder python=3.10 -y && conda activate tinyfeeder
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121   # match your CUDA
git clone https://github.com/Drwae/TinyFeeder.git && cd TinyFeeder
pip install -e ".[paper,prep,dev]"
pytest -q
nvidia-smi > runs_env_gpu.txt; python -c "import torch;print(torch.__version__, torch.version.cuda)" >> runs_env_gpu.txt
```

## 1. Download and convert AV-FFIA

Dataset: Cui *et al.*, "Multimodal Fish Feeding Intensity Assessment in
Aquaculture", IEEE T-ASE 2024 — https://zenodo.org/records/11059975
(27,000 two-second audio-visual clips, four intensity levels). Download the
video and audio archives and extract them, e.g. to `/data/AV-FFIA/`.

```bash
# inspect first: class counts, pairing of audio/video, recording sessions found
python scripts/prepare_avffia.py --video-root /data/AV-FFIA/video_dataset \
       --audio-root /data/AV-FFIA/audio_dataset --inspect
# convert (one 224x224 frame + 128x128 log-Mel per clip)
python scripts/prepare_avffia.py --video-root /data/AV-FFIA/video_dataset \
       --audio-root /data/AV-FFIA/audio_dataset --out data/avffia/avffia_224.npz --workers 16
```

The split unit is the **recording session** (`group_id`), not the clip:
clips cut from the same recording never appear in different splits.
If `--inspect` reports fewer than ~10 sessions, adjust `--group-depth`
and re-inspect before converting. Keep `data/avffia/avffia_224_clips.csv`:
together with `runs/avffia/splits.json` it defines the exact split and is
released with the results.

## 2. Profile the search space on the Jetson (hardware-aware NAS)

On the Jetson Nano, in the same repository:

```bash
sudo nvpmodel -m 0 && sudo jetson_clocks          # record the power mode you use
python deploy/profile_device.py --n 1000 --img 224 --mel 128 --out jetson_latency.csv
```

Copy `jetson_latency.csv` to `data/jetson_latency.csv` on the GPU server.
(Without it the search falls back to host-CPU latency, which must then be
reported as such.)

## 3. Train and evaluate everything (GPU server)

```bash
python scripts/run_pipeline.py --config configs/avffia.yaml --device cuda --workers 8
```

Stages: data split → teachers → lightweight baselines → HW-NAS → Stage 1
(FP32) → Stage 2 (mixed-precision QAT) → Stage 3 (multi-teacher KD) →
evaluate (test predictions of every model) → export (ONNX of every model).
The run can be interrupted and resumed; finished stages are skipped.

## 4. Benchmark on the Jetson

Copy `runs/avffia/tinyfeeder.onnx` and `runs/avffia/onnx/*.onnx` to the Jetson, then:

```bash
python deploy/calibrate.py --config configs/avffia.yaml --n 500          # on the GPU server (training split only)
bash deploy/benchmark_jetson.sh runs/avffia/tinyfeeder.onnx tinyfeeder_final int8
for f in runs/avffia/onnx/*.onnx; do n=$(basename "$f" .onnx); bash deploy/benchmark_jetson.sh "$f" "$n" fp16; done
python deploy/parse_jetson.py runs/avffia/jetson > runs/avffia/jetson_benchmark.json
```

## 5. Build the tables

```bash
python scripts/paper_tables.py --run runs/avffia --jetson runs/avffia/jetson_benchmark.json
```

`runs/avffia/tables.md` / `tables.json` contain: split statistics, the
model comparison (parameters, size, FLOPs, accuracy with session-level
bootstrap CI, macro/weighted F1, CPU and Jetson latency, FPS), the confusion
matrix, the compression stages, exact McNemar tests with Holm correction and
cluster-bootstrap CIs, robustness to input corruption, and the NAS / QAT /
KD settings actually used.

## 6. Release

Commit `runs/avffia/` without the large teacher checkpoints (they are
listed in `.gitignore`) and publish a new GitHub release; Zenodo archives
it automatically. Upload the teacher checkpoints to the Zenodo record as
additional files if needed.
